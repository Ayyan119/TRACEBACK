# TRACEBACK AI — Gemini LLM 503 Unavailable Diagnostic Report

## 1. Executive Summary & Root Cause
- **Root Cause**: The HTTP `503 Service Unavailable` errors reported by `ChatGoogleGenerativeAI` are returned directly by Google Gemini's API servers (`generativelanguage.googleapis.com`). They occur when high burst concurrency (7 to 12 LLM requests generated per investigation, including parallel branches) exceeds Google's Free Tier **5 Requests Per Minute (5 RPM)** quota and capacity limits.
- **Exact Error Message**:
  `503 UNAVAILABLE: {'error': {'code': 503, 'message': 'This model is currently experiencing high demand. Spikes in demand are usually temporary. Please try again later.', 'status': 'UNAVAILABLE'}}`
- **Quota & Rate Limit Status**: Google Gemini Free Tier enforces **5 RPM (Requests Per Minute)** and a **20 Requests Per Day** quota on preview models. A single investigation execution fires 7+ requests in ~5 seconds, causing Google's API to shed load and issue 503/429 status codes.

## 2. Component & Architecture Audit

### A. Failing Component
- **Remote Provider**: Google Gemini API Infrastructure (`generativelanguage.googleapis.com`).
- **Local Wrapper**: `langchain_google_genai.chat_models.ChatGoogleGenerativeAI`.
- **Primary Model Configured**: `gemini-3.7-flash` (with `temperature=0.1`, `max_retries=0`).

### B. Concurrency Analysis
One single TRACEBACK investigation executes the following LLM-driven nodes:
1. `process_images` (Vision LLM call) — *runs in parallel branch with process_documents*
2. `process_documents` (Document LLM call) — *runs in parallel branch with process_images*
3. `reason_with_tools` (Tool reasoning LLM call)
4. `incident_analyzer` (Self-RAG decision LLM call)
5. `analyze_evidence` (Evidence synthesis LLM call)
6. `generate_hypotheses` (Hypothesis ranking LLM call)
7. `generate_final_report` (Final RCA report LLM call)

**Total LLM Calls Per Investigation**: **7 to 12 calls** (depending on tool/investigation loops).
When fired concurrently within 2–5 seconds, call #6 triggers Google's 5 RPM free tier rate limiter, resulting in 503 Service Unavailable / 429 Resource Exhausted.

### C. Retry Behavior
- LangChain `ChatGoogleGenerativeAI`: `max_retries=0` configured in `app/models/llm.py`.
- SDK-level `google.genai._api_client`: Performed up to 10 internal retries with exponential backoff on 429/503 errors, accumulating execution delays.

### D. Audit of Exception Handling & Fallbacks
- When Gemini returns 503/429, the system catches the exception and falls back to dynamic evidence-based heuristics (`HypothesisRanking` / `EvidenceAnalysis` / `FinalInvestigationReport`).
- **Hardcoded RCA Check**: **CONFIRMED REMOVED.** No static PostgreSQL `customer_id`, fixed 94.5% confidence, or arbitrary connection pool strings are fabricated. All fallback values derive dynamically from the incoming incident description and service parameters.

## 4. Recommended Action Plan
1. **Pacing / Rate-Limit Delay**: Implement a lightweight delay or batching mechanism between LangGraph nodes when running on Free Tier API keys (5 RPM limit).
2. **Multi-Model / Provider Failover**: Ensure seamless failover between Google Gemini and Groq (`llama-3.3-70b-versatile`) when Google API returns 503/429.
